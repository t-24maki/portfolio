# Takuma Nishimaki — Portfolio

[tnishimaki.com](https://tnishimaki.com/) のソースコードです。Next.jsの静的エクスポートを使用しています。

## ページ構成

| ページ | URL | 内容 |
| --- | --- | --- |
| About | `/` | プロフィール、支援テーマ、Web発信、講義・講演、掲載情報、論文・学会発表、連絡先 |
| Works | `/works/` | 全作品の一覧と分類タグによる絞り込み |
| 合同会社prop | `/prop/` | 企業情報、取引実績、企業ロゴ |

個別のWebツールは `/tools/` 配下で引き続き公開します。旧ページのURLは新ページへの移動案内として残しています。

過学習シミュレータ（`/tools/overfitting/`）は、学習用・検証用の点を1枚の散布図に重ね、モデルの複雑さによる予測曲線と誤差の変化を比較する教材です。山と谷がある三次曲線から架空データを生成します。計算処理は `lib/overfitting.mjs`、作品一覧の設定は `data/works.js` にあります。

5つのツールのSNS共有画像は `public/images/og/` のJPEG（1200×630px）です。Worksの画像をもとに、画面全体が収まる横長のレイアウトで用意しています。`data/works.js` の `shareImage` を `components/Common/SEO.js` がページのURLに応じて使用し、その他のページはサイト共通画像を使用します。

「データの庭」のOGP画像は `public/images/og/data-garden-v3.png`（1200×630px）です。既存のロゴと花を参照した紹介用イラストで、プレイヤーの結果画像とは別です。ヘッダーに近い小さなアイコンと素朴な書体のタイトルを縦並びにし、左側の上下中央に配置しています。説明文は入れていません。Worksの紹介画像にも共用し、`data/works.js` の `shareImage` からOpen Graph・Xカードの画像URL、サイズ、形式、代替テキストを設定しています。画像生成のプロンプトと参照素材は `data/miracle-garden-art.json` に記録しています。公開サイトを更新すると、この画像がURL共有時のプレビューに使われます。

## ローカル開発

検証環境はNode.js 22です。

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3000
```

## 検証と公開用ビルド

開発サーバーを停止してから実行します。開発とビルドで共通の `.next/` を使用するため、同時に実行しないでください。

```sh
node --test tests/*.test.mjs
npm run build
```

公開用ファイルは `out/` に生成されます。ソースコードをGitへpushした後、FileZillaで `out/` の中身を公開ディレクトリにアップロードします。

詳しい差し替え手順と旧ページの扱いは [DEPLOYMENT.md](DEPLOYMENT.md) を参照してください。

## データの庭

Worksの「データ・統計」に掲載しています。公開URLは `https://tnishimaki.com/tools/miracle-garden/`。検索対象とし、サイトマップにも追加しています。

`npm run dev -- --hostname 127.0.0.1 --port 3000` で起動し、[http://127.0.0.1:3000/tools/miracle-garden/](http://127.0.0.1:3000/tools/miracle-garden/) を開きます。初回は上記の `npm ci` を実行してください。独立したゲーム画面を使用し、既存ページのレイアウトは維持しています。

- 花は毎ゲーム、同じコスモスに固定。水・肥料との相性と成長傾向は新しい庭ごとに抽選し、ゲーム中は固定します。実在の花をモチーフにしていますが、成長や色の変化はゲーム用です。
- 花の大きさは個々の観測された長さに比例して、基準サイズの0.55〜1.2倍へ連続的に変わります（100cmで上限）。通常は淡いピンクの一重、70cm以上で濃いピンクの八重、85cm以上で花びら全体がクリーム色・黄金色の多重の花に変わります。花の変化を発見する楽しみを残すため、ゲーム画面・あそびかたには見本やしきい値を表示しません。判定は画面の小数1桁と揃え、84.96cmは85.0cmとして黄金色にします。0cmは開花せず、未開花の結果も先に見せません。育成画面・履歴・本番・保存画像で共通の規則を使い、散布図の色と形は引き続き肥料を表します。見た目による抽選・加点はありません。
- 背景と花は `public/images/miracle-garden/` のPNG素材を使用します。内蔵 image_gen による生成プロンプトと素材一覧は `data/miracle-garden-art.json`。花は透過PNGを共用し、背景を含めた素材の合計は約700KBです。肥料はじょうろ・ボトルのSVGアイコンで、容器・散布図・凡例・履歴の丸／ひし形／三角は `TreatmentArt.js` の共通描画を使います。
- 茎・葉は株のIDから3系統の形を決め、長さに応じて葉を増やします。育成画面と履歴で同じ株の形を保持し、ゲームの乱数・得点には影響しません。茎の先端の高さは形によらず観測値に一致します。長さの目盛りは不透明な専用パネルに置き、鉢の土面を0cmに合わせています。ロゴはB案「芽とひかり」を採用し、深緑と金色の2色のSVGをヘッダーと結果画像で共用します。
- 散布図は緑の軸と横帯、点線の縦グリッドを使います。選択中の水量を縦のガイドで示しますが、未調査の成長量は描きません。点の色・形・座標とキーボード操作は維持します。縦軸の100cmは初期表示の上限で、観測値が超えれば120cm、140cm…と20cm単位で自動拡張します。育成画面・履歴も同じ目盛りを使い、長さを100cmで打ち切ることはありません。
- 実験は12回、同じ条件で3株ずつ。水0〜100ml（1ml刻み、数値欄は等幅・固定幅にして単位の位置を固定）、肥料は水だけ・肥料A・肥料Bの3択です。同じ条件の再試行も1回使います。
- おためしは左に育成画面と操作欄、右に分析ノートを並べます。育成の描画領域は本番よりコンパクトにし、ノートを見ながら水・肥料を変更できます。小画面では縦に並べ、ノートを見ている間も操作欄が上部に残ります。今回の3株は育成後に下段の履歴へ追加。履歴は実験順の横一列で、小画面では横スクロールできます。全区画・育成画面・散布図の高さの上限は共通。0cmは種と0、未実験は空いた区画で区別します。過去の区画を押すと入力欄とノートに条件が反映されます。
- 冒頭の2文で「12回のおためし → 本番の合計点」を案内し、詳しい操作は「あそびかた」にまとめています。分析ノートの散布図は横軸が水、縦軸が長さ、肥料が丸・ひし形・三角。観測値だけを描き、点や履歴から水・肥料を操作欄に戻せます。平均の表示切替は設けず、本数・失敗を含む平均・個々の長さは記録の詳細に残します。未調査には点がなく、失敗は0cmに残ります。重なった点の本数は詳細で確認できます。
- 12回を終えると本番準備へ。選択中の条件を引き継ぎ、記録から変更して一度のボタン操作で本番を開始します。本番は3株を順に咲かせ、実際に咲いた分だけ得点を表示。1cm＝1点で、各花の表示値（小数第1位）を合計したものが得点です。合計は0.1点単位の整数で計算し、浮動小数点の誤差を避けています。結果・自己ベスト・共有文・保存画像は同じ桁数で表示します。結果の一括表示と動きを減らす設定にも対応します。
- 個体差は平均0、全条件共通の標準偏差4cmの正規分布。平均成長量に足して、負なら0にします。観測値は連続値のまま保持し、表示と得点で丸めます。分析ノートなどでは0より大きく0.1未満の値を「0.1未満」と表示します。本番の数値は足し算できるよう小数1桁に揃え、微小な正値を0.0cmと表示しても、観測データや開花の判定では失敗扱いにしません。
- 隠れた成長傾向は3系統です。`broad` は4次の平らな頂上、`focused` は比較的狭い2次の山、`waterSensitive` は過剰な水の側で急に低下する左右非対称の山。すべて滑らかに一つの適量へ向かい、負の平均も許します。モデル式は `peak + boost - falloff * (abs(water - optimum - shift) / width)^power`（水は0〜1に正規化）。`width` は左右と肥料で変わります。
- 適量は25〜75ml相当から毎回抽選。肥料で適量が±9〜14ml、幅が0.92〜1.08倍変化するため交互作用があります。最良の肥料は毎回選ばれ、水だけが最良になることもあります。最良のピークは80cmに統一し、他は10〜16cm低く仮置き。最高到達点は揃えていますが、形による探索難易度は同一ではありません。相性は本番まで固定され、結果の乱数だけ毎回新しく引きます。隠れた曲線や正解は表示しません。
- 実験記録はメモリ上のみ。再挑戦・ページ再読み込みで消去し、以前の庭や本番の結果を実験集計に混ぜません。自己ベストだけlocalStorageに保存。旧モデル・旧9株ルールとは記録区分を分け、今回の見た目の変更では直前の1種類・本番3株ルールの自己ベストを引き継ぎます。保存不可でも遊べます。

調整場所は `data/miracle-garden.mjs` の `GARDEN_CONFIG`。`title`・`titleRuby` で名称と一部のルビ（現在は「庭」に「にわ」）、`scoreDecimals` で本番の花の表示と得点に共通の小数桁数（現在1）を変えられます。`flowers` は固定の花の一覧、`flowerCount` は先頭から使う種類数です。`bloom` で花のサイズ倍率・上限の長さ・見た目のしきい値・画像・名称、`art.background` で背景画像を調整できます。実験回数・株数・標準偏差・水の範囲・目標・演出時間・成長傾向の `model.profiles` とその範囲も集約しています。`water.initial` は範囲内の整数にし、花と肥料には一意のIDを使ってください。`none` は水だけのIDです。

自己ベストは表示値の合計を得点にする保存キー `miracle-garden-best-v5` に記録します。以前の整数記録（v3）・小数2桁記録（v4）は元の各花の長さを復元できず、新方式で再計算できないため比較に混ぜず、削除も行いません。名称変更だけでは記録区分は変わりません。URL・素材のパスは引き続き `/tools/miracle-garden/`・`/images/miracle-garden/` を使います。

ヘッダーはロゴと「あそびかた」「解説」の補助メニューだけにし、両方に同じ線幅のアイコンを付けています。自己ベストはゲーム説明の横に表示し、隣にランキングへのボタンをまとめ、成績と案内を分けています。小画面では成績欄を説明の下に置きます。「解説」はゲームを離れずに読めるダイアログです。開発意図、データ量と推定の確かさ、ばらつき、散布図、仕事での応用例、学習・教育で自由に利用できる旨は `components/MiracleGarden/Explanation.js` で編集できます。初期画面や結果画面で自動表示しません。学びの4項目（ばらつき・データ量・グラフ・仕事での応用）をまとめ、教育利用の案内の後に「ゲームのしくみ」を独立して配置しています。平均成長量・肥料との交互作用・正規分布（Box–Muller法）・負値の0補正・表示値の得点化を、折り畳まずに説明します。数式はKaTeXのHTML＋MathMLで表示し、数式フォントとCSSはローカルに同梱します。外部の参考資料欄は設けていません。

計算と状態遷移は `lib/miracle-garden.mjs`、画面は `pages/tools/miracle-garden/index.js`、大きな育成画面と履歴は `components/MiracleGarden/ExperimentGarden.js`、見た目は `styles/MiracleGarden.module.css` です。

`node --test tests/miracle-garden*.test.mjs` で、負値処理・失敗を含む集計・正規乱数・相性固定・新規ゲームの変更と記録分離・各傾向の形・肥料との交互作用・予算制限・本番の一度だけの実行・設定引継ぎ・小数得点の計算と保存・旧整数記録の保全を確認できます。

試遊では「12回の途中で傾向が見えるか」「同じ条件を確かめ直す意味があるか」「最後の数回まで試したいことが残るか」「大きな育成画面と履歴・散布図を使い分けられるか」を確認します。標準偏差4・8・0は設定で比較可能で、プレイヤー向けのモード選択は追加していません。子ども・大人による楽しさや継続率の検証はこれからです。

### 庭の演出・共有

- 開花完了後に、得点に応じた紙吹雪を一度だけ流します。0点では0枚、得点が上がるほど増え、最大100枚。`celebration` の設定で量・時間を変更できます。数秒後に描画を片付け、「動きを減らす」では表示しません。演出の乱数はゲームの乱数と独立し、保存画像には紙吹雪を含めません。
- 本番の3株の実際の高さに応じて描画。0cmは種、未開花は芽です。180点で緑のアーチ、210点で蝶、240点で光を仮置きし、本番の得点に応じて装飾が増えます。おためし画面には装飾の依頼枠を設けません。
- 結果画面は庭・合計得点・各花の長さ・再挑戦を中心に表示。目標点・称号・最多長・本数カウンター・重複する本番記録は表示せず、共有は常設し、実験の振り返りだけを折りたたみます。各花の長さは背景を敷いた太字で表示し、狭い画面では文字サイズを補正します。
- X・LINE・Blueskyの共有ボタンを完成後に常設し、得点・3本の長さ・ハッシュタグ・公開URLを入れた投稿画面へ進めます。画像の生成を待たずにSNS共有とコピーが使えます。画像保存・結果文コピー、対応端末の共有メニューも使えます。SNSの投稿確定はプレイヤーが行い、個別SNSへの画像の自動添付はしません。画面と共有画像は `components/MiracleGarden/GardenPostcard.js`、結果文と画像化は `lib/miracle-garden-presentation.mjs` が担当。画像・文章に隠れた正解は含めず、ローカルURLは共有文から除きます。
- 保存画像は、表示中のSVGに背景と花のPNGを埋め込んでからブラウザ内で生成します。素材の取得に失敗した場合は不完全な画像を保存せず再試行を案内します。外部への自動投稿・成績送信はありません。ランキングへの送信は、完成後にプレイヤーが登録したときだけ行います。アルバム・突然変異・混合分布は今回の対象外です。


### 世界ランキング（Firebase Spark）

専用Firebaseプロジェクトは `data-garden-game`（管理画面名 `Data Garden`）。Sparkの無料枠で、匿名認証とCloud Firestoreだけを使用します。Cloud Functions・課金アカウント・Firebase Hostingは使いません。既存の静的サイト配信は維持します。

- 自己ベストの隣にある「ランキング」で上位50件と、自分の順位・登録人数・最高記録を閲覧。完成後の「ランキングに登録」で名前（1〜12文字）を入力して送信します。自動登録はしません。
- 閲覧だけならログイン不要です。登録時にFirebaseの匿名認証でブラウザ単位の参加者を区別し、各参加者につき最高記録を1件だけ保存します。ゲーム開始時にはFirebaseへの通信を行いません。
- スコアは表示された花の長さを合計し、0.1点単位の整数で保存。同点は同順位（1位、1位、3位）、同点の表示順は先に登録した順です。全体件数と、自分より高い得点の件数をFirestoreの `count()` で集計し、「123位 / 1,234人」のように表示します。50位以下も順位が分かり、未登録の場合は順位を表示しません。人数はプレイ回数やアクセス数ではなく、現在公開記録がある匿名参加者の数です。
- 本人だけが自分の記録を作成・更新・削除できます。他人の匿名UIDを指定しても、その記録への書き込みはFirestoreルールで拒否します。最高点より低い点や同点では上書きせず、同時送信はトランザクションで整合性を保ちます。表示名はランキングの自分の順位欄から、得点更新なしで変更できます。名前だけの変更では得点・各花の長さ・達成日時を維持し、参加人数・同点の表示順も変わりません。Firestoreの差分検査で名前以外の変更を拒否し、名前の入力制限も再検証します。削除済みの記録は再作成せず、同時に自己ベストが更新されても古い得点を戻しません。名前を変えても別の参加者にはなりません。
- Firestoreルールで、許可した項目だけであること、名前の長さと制御文字、得点・各花の長さが非負の安全な整数であること、本数、各長さと合計の一致、登録時刻がサーバー時刻であることを検査します。100cmや300点での打ち切りはありません。
- 公開データは表示名・得点・各花の表示長・登録時刻と、ドキュメントIDとしての匿名UIDです。メールアドレスや実験履歴・隠れた相性は送りません。自分の公開記録はランキングから削除できますが、ブラウザのデータ削除・端末変更後は本人として更新・削除できなくなります。
- **得点をサーバーで再計算する構成ではありません。** 自分の得点と長さを整合するように偽装する不正や、別の匿名アカウント作成までは防げません。競技性・公開規模に応じて、将来Blazeとサーバー検証を検討します。
- ゲームはオフラインでも遊べます。記録の送信・閲覧・削除には通信が必要です。操作はサーバーの応答を待って完了を表示し、ランキングはキャッシュを最新情報として表示しません。送信でタイムアウトした場合は登録済みの可能性もあるため、再送しても重複しない構成にしています。
- ランキングは開いたときと「更新」を押したときだけ取得し、常時購読しません。アプリが取得する一覧は上位50件と本人の記録を最大1件。加えて全体人数と本人より高得点の人数を集計し、全件の記録をダウンロードしません。取得中に他の登録があれば各問い合わせの時点が少しずれる場合があります。Sparkの利用枠を超えた場合は通信エラーを表示し、課金プランへ自動変更しません。
- 全体集計には件数制限のないクエリの許可が必要です。[Firestoreでは集計と通常クエリに同じルールが適用される](https://firebase.google.com/docs/firestore/query-data/aggregation-queries#security_rules_for_aggregation_queries)ため、公開ランキングの一覧読み取りは件数制限なしで許可します（通常のアプリ表示は50件のまま）。元から公開される記録だけが対象で、他人の更新・削除禁止や入力検証は維持します。`count()` の利用分も無料枠に算入されます。

Web用Firebase設定は公開情報として `data/miracle-garden-firebase.mjs` に置き、サービスアカウント鍵は使いません。Firestoreは `nam5`。Google Analyticsやメール・SNSログインは有効にしていません。以前のローカル自己ベストは構成が異なるため自動送信せず、この画面で完成した庭を登録します。

調整元は引き続き `data/miracle-garden.mjs` です。`scripts/prepare-garden-ranking.mjs` が設定から記録区分・本数・得点単位を生成し、`data/miracle-garden-ranking-schema.mjs` と `firestore.rules` に反映します。モデル設定変更時は別の区分になり、過去の記録と混ざりません。数式そのものを変えた場合は生成スクリプトの `protocol` も更新してください。生成ファイルは手で編集せず、変更後にルールをデプロイしてサイトを再ビルドします。


`npm run build` はルールの生成も実行しますが、Firebaseへのデプロイは行いません。公開サイト用には開発サーバーを止めてビルドし、再生成した `out/` を従来の配信先にアップロードします。サイト全体をFirebase Hostingへ移す設定は行いません。
